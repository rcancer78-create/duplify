# Duplify

Поиск одинаковых файлов на Windows: сравнение по размеру и SHA-256, просмотр групп дубликатов, выбор сохраняемой копии и удаление в Корзину либо перемещение в отдельную папку.

*A Windows duplicate-file finder built with WPF and .NET 8. Russian interface, local processing, and review before file actions.*

**Публичная beta.** Перед массовыми действиями проверьте результат на небольшой тестовой папке и сохраните резервные копии важных файлов. Приложение не заменяет резервное копирование.

## Возможности

- Двухэтапное сканирование: группировка по размеру, затем хеширование кандидатов.
- Учёт NTFS hardlink и исключение junction/symlink при обходе.
- Превью изображений, фильтры и выбор сохраняемых копий.
- Массовый разбор по предпочитаемой папке, имени и другим правилам; неоднозначные группы остаются для ручного выбора.
- Повторная проверка выбранного файла и сохраняемой копии перед действием; изменившиеся или недоступные файлы пропускаются.
- Корзина по умолчанию и отдельное подтверждение постоянного удаления.
- Перемещение с разрешением конфликтов имён, журнал действий и локальные настройки.

Сравнивается содержимое файлов. Поиск визуально похожих изображений, нечётких совпадений и пустых файлов в этот режим не входит.

## Запуск из исходников

Нужны Windows 10/11 и [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0). Откройте PowerShell в корне скачанного или клонированного репозитория:

```powershell
dotnet restore Duplify.sln
dotnet build Duplify.sln -c Release --no-restore -warnaserror
dotnet run --project Duplify.csproj -c Release --no-build
```

Выберите папку, выполните сканирование, просмотрите группы и отметьте лишние копии. Оставьте хотя бы одну копию в каждой группе неотмеченной. Затем выберите удаление или перемещение и проверьте подтверждение действия. Подробности — в [руководстве](docs/usage.md).

## Ограничения и данные

Перед удалением или перемещением повторно проверяются размер, SHA-256 и текущая идентичность выбранного файла и хотя бы одной неотмеченной физически отдельной копии. Сохраняемая копия удерживается открытой без разрешения записи и удаления до завершения действия. Если выбранный файл изменился, проверка недоступна или подходящей сохраняемой копии нет, действие для этого файла пропускается; причина попадает в итоговый отчёт и журнал. На время операций запуск нового сканирования блокируется.

Эти проверки не являются атомарной транзакцией файловой системы. Между последней проверкой пути и системным удалением или перемещением остаётся возможность внешнего переименования или подмены пути. Приложение не блокирует всё дерево. Для важных каталогов остановите изменяющие их фоновые процессы и сохраняйте независимые резервные копии.

Если в группе отмечены все копии, удаление не начинается: нужно снять отметку хотя бы с одной. Обхода этого ограничения через подтверждение нет. Если отправить файл в Корзину не удалось, постоянное удаление требует отдельного согласия и новой проверки файлов после диалога. Возможность восстановления из Корзины зависит от Windows и используемого диска.

Настройки, журнал операций и логи хранятся в `%APPDATA%\Duplify\`. Журналы могут содержать полные пути к файлам: проверяйте их перед публикацией. Сканирование выполняется локально.

## Проверка и сборка

```powershell
dotnet restore Duplify.sln
dotnet build Duplify.sln -c Release --no-restore -warnaserror
dotnet test Duplify.sln -c Release --no-build --no-restore --nologo --blame-hang --blame-hang-timeout 2m
```

[Windows CI](.github/workflows/ci.yml) собирает решение и запускает настоящие xUnit-тесты. После успешного задания тестирования отдельное задание создаёт архив Windows x64 с включённым .NET runtime. Артефакты и результат конкретного запуска доступны во вкладке Actions. Автоматические тесты не заменяют ручную проверку интерфейса и разных файловых систем.

Переносимую сборку можно создать локально:

```powershell
dotnet publish Duplify.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o artifacts/portable/Duplify
```

Запускайте `Duplify.exe` из полученного каталога вместе с остальными файлами. Отдельный .NET runtime пользователю не нужен; настройки по-прежнему хранятся в профиле Windows.
